# Shared interface and browser edition

The visible product name is **Jinni**. An original blue-and-gold lamp mark appears in the header and favicon. It is drawn with local SVG paths and theme-aware colours. The repository/deployment path, `my-jinni-theme`/`my-jinni-sound` preferences and IndexedDB name remain unchanged so existing links and saved browser sources continue to work. Extracted-text downloads use `jinni-source.txt`.

On 2026-10-17 the user requested an additional browser application hosted on GitHub Pages. This explicitly extends the earlier desktop-only delivery decision. The Electron application and Python API remain available with their existing contracts.

The user subsequently requested a general decision workspace with all five challenge scenario areas, compact context tools, animation and optional sound. Contract v0.5 is defined in [GENERAL_DECISIONS.md](GENERAL_DECISIONS.md). Decision comparison is now the main view; the local library/passage search opens on demand and the detailed activity itinerary remains a closed optional example. Existing themes, local sources, PDF extraction and planner behaviour are preserved.

Both platforms now use **the same `web/index.html`, CSS and application modules**. Electron loads these assets at `jinni://app/index.html`; Pages serves the static build. Interface edits apply to both experiences rather than a second copied renderer. `web/platform.mjs` chooses the existing restricted desktop bridge or browser-local calculation/storage. Desktop comparisons and activity plans remain authoritative Python API responses; the browser keeps the parity-tested pure JavaScript engines. No fixture success replaces a failed desktop request.

The page opens directly at the decision workspace. A short title, optional **Try example**, topic choices and concise fictional-preset label replace the large hero, repeated onboarding, free/account claims and how-it-works section. Useful constraints, units, trade-offs, no-match/errors and privacy remain. Top priorities appear once; score contributions, exclusions and source limitations stay collapsed. External repository/desktop links are browser-only. Appearance, optional waves/sound, all five languages, source tools and the detailed activity planner remain available.

## What users can do

- Compare five configured scenario areas: fictional market context, travel, student opportunities, sustainable choices and your own decision. Adjust criterion weights and optional hard minimum/maximum limits; inspect the highest preference fit, all feasible options, actual measures, score contributions, exclusions and two-source provenance. Presets use simulated data and make no live-price, routing, forecast, suitability or independently verified impact claims.
- Use an optional expanded JSON editor in the own-idea scenario to replace criteria and both source datasets. Limits are 50 options, 10 criteria, 20 constraints, weights from 0 to 100 and finite numbers with magnitude at most 1e12; money uses nonnegative integer pence internally. Money constraints are entered as exact pounds in the interface. Custom source names and simulation flags are supplied metadata, not verification.
- Open **Detailed activity itinerary** for the preserved fictional Glasgow example. Calculate one activity and up to two alternatives using origin, supported date, departure/return times, interests and a GBP budget. No account, key or local server is required.
- Save pasted text, UTF-8 TXT/Markdown and text PDFs in this browser's IndexedDB. The limits are 20 sources, 5 MiB per file, 150,000 extracted characters and 40 PDF pages. Password-protected, scanned/textless, corrupt and oversized PDFs fail without a partial import.
- Select sources and find up to six exact matching passages with keyword search. Open the original extracted text, including PDF page numbers and fictional-content labels, or download extracted text before clearing browser storage.

This is a static browser workspace. It does not call the desktop's loopback API, require GitHub login, send documents/searches to a server, or collect provider keys. It serves assets from the same site; PDF.js and its worker, fonts, character maps and WASM files are included in the deployment. No CDN is needed at runtime. Initial loading and file assets still require access to the site; offline installation is not provided.

Cloud AI generation is not available on this site: GitHub Pages cannot host the existing Python provider service. Search results are labelled original excerpts, never represented as AI answers. Use the desktop edition for provider-backed questions. Arbitrary cities/dates, live events/fares, OCR and cloud sync remain outside scope.

The library is local to this browser profile and site origin, separate from desktop SQLite. Clearing site data, private browsing policies, storage quotas or browser eviction can remove it. Download important sources. Selections reset on reload; saved sources persist. Storage failure leaves decision comparison and the activity planner usable and displays an error for library actions. No source selection or question is inferred from decision inputs. **Library & search** opens a modal tool panel; Escape or **Close tools** closes it and returns focus. Keyword results remain original excerpts, not cloud AI answers.

## Appearance and accessible controls

The header's native **Language** selector offers English, Simplified Chinese, French, Japanese and Russian, displayed using their autonyms. English is the default; the chosen interface language is remembered under `jinni-locale`. When browser storage is blocked, switching still works for the current visit. `shared/i18n.js` provides explicit text/attribute bindings; `web/locales.js` supplies application-owned translations and `web/i18n.mjs` connects dynamic controls. The build includes these local assets without an external translation service.

Changing language updates interface labels, explanations, errors, formatted numbers and dates. It preserves current inputs, source selection, custom JSON and the calculated comparison. Existing calculated data is rendered again for presentation; changing language does not run the decision engine, repeat keyword retrieval or send a network/AI request. Money remains GBP and activity times remain Europe/London. The selector uses autonyms so users can return to a familiar language. Header controls remain accessible on narrow screens; Appearance uses its icon and accessible current-mode label when space is limited.

Translations are limited to controlled interface copy and known preset labels. User-created names, custom labels/units/JSON, source identities, notes and exact excerpts remain original and inert. This is interface localization, not multilingual retrieval or source translation: a translated interface does not make an English passage match a differently worded or cross-language query. The browser edition still has no cloud AI generation or provider key input.

The browser workspace uses light and dark palettes, clearer cards, friendly empty/no-match states and compact expandable explanations. The **Appearance** dropdown in the header offers visual **Light**, **Dark**, and **Match device** preview tiles with native radio controls. Visitors can return to Match device after selecting a manual mode; it follows later device changes. The choice is remembered in `localStorage` under `my-jinni-theme` and syncs to other open tabs. Theme switching still works for the current visit when storage is restricted. Theme initialisation runs before the stylesheet to avoid showing the wrong saved palette first. Done or Escape closes the dropdown and returns focus to its control.

One set of colour-coded topic cards chooses Money choices, Getting around, Student life, Greener choices or My own idea. Each factor uses an everyday importance dropdown: Suggested, Not important, A little important, Important, Very important, or Fine-tune. Suggested preserves the preset's exact original weight; the other choices use 0, 25, 50 or 100. Exact sliders/numbers only appear after choosing Fine-tune, so custom precision remains available without dominating the normal flow. Zero still excludes a factor from scoring; a spending/time limit still applies. Changes clear prior comparisons, and an empty result remains distinct from an error.

Money amounts display as **£** throughout budget controls, result cards, tables and expanded explanations. For example, the preset's internal 2500-pence limit appears as a £25 budget and an 800-pence option as £8.00. Inputs convert back to exact integer pence before calling the unchanged decision core. Other dimensions retain their meaning: 70 minutes displays as 1 hr 10 min and 2200 g CO2e as 2.2 kg CO₂e; limit labels explicitly state their input units. Custom labels are retained. Original API/JSON units and scoring contracts are unchanged.

**Try example** calculates the travel preset and moves focus to the result. Spending limits appear first; other limits remain under **More limits (optional)**, with active values visible while closed. Closing the section never disables them. Invalid required amounts reopen it and receive focus. **Change my choices** returns focus without resetting inputs; **Use suggested settings** restores the preset. Editing inputs invalidates earlier results. Changing custom JSON requires Apply again before comparison or explicit AI context; applying validates through the platform's authoritative calculation path.

Both comparison and activity submissions are asynchronous, have duplicate-submit guards and ignore outdated responses after a scenario/form change. No delayed desktop response can restore an obsolete result. `web/ui-context.mjs` exposes cloned current preferences/decision requests and selected source IDs to the separate desktop AI dialog, plus context-invalidation listeners and an original-source viewer. These readers contain no keys. Invalid/unapplied current inputs are rejected before a context request. Source viewing marks an exact quoted substring using text nodes and a `mark` element without changing the surrounding original text.

Amount limits pair a larger slider with an editable number field and a visible unit: £, minutes, hours, days, carbon grams or rating points. The accompanying text shows readable equivalents such as 1 hr 10 min and 2.2 kg CO₂e. Arrow keys change monetary limits by one penny and other limits by one unit; Page Up/Down changes by ten steps. Typing an amount outside the suggested slider range expands that range without clamping the amount. Fine-tune importance uses its own clearly labelled / 100 points field, endpoint labels, live coloured track and screen-reader value text; these points are not currency or time. Fractional exact importance and existing integer-pence calculations are preserved.

Subtle red, green, blue and yellow SVG waves drift behind the page using two local, transform-only CSS layers. The **Animated background waves** checkbox under Appearance pauses motion and remembers the setting under `my-jinni-waves`; changes sync across tabs and storage restrictions leave the switch usable for the visit. Device reduced-motion preferences always stop the waves, with a clear status and disabled animation switch while the device preference applies. The background cannot intercept clicks or appear in the accessibility tree. No external images, animation package or framework is added.

The optional itinerary keeps native origin/date/budget selects and the multi-interest dropdown. Library sorting, exact-pound custom budgets, keyboard dropdown navigation, Escape and focus return are preserved. Both the library and itinerary start closed to keep the decision workspace compact.

An optional inspiration dropdown sets interests and budget while preserving the visitor's selected time and location. **Start fresh** restores the scenario defaults without changing sources or appearance. Correctable budget, interest and time-window errors appear beside the relevant control, mark it invalid and move keyboard focus there. On narrow screens, a successful calculation brings the visitor to the result heading, respecting reduced-motion preferences.

The **Add a source** dropdown groups pasting a note, importing a file and trying the fictional guide, with short explanations. New sources are selected automatically and receive keyboard focus. Select all and Clear selection make larger libraries easier to search. A source-removal dialog defaults to keeping the document; cancelling or pressing Escape leaves data unchanged. Confirmed deletion removes the stored source and returns focus to Add a source. These controls preserve the existing import bounds, local-only storage and exact selected-source search.

Labels, visible focus rings, contrast-aware controls, 44px primary interaction targets, reduced-motion support and mobile-sized form text make the interface easier to operate. Browser tests check common text at WCAG AA's 4.5:1 contrast threshold in both modes, keyboard dropdown/theme operation, saved/device/cross-tab themes, blocked storage, and layouts at 320, 390, 768 and 1280px. These automated checks are not a claim of a complete accessibility audit or human usability review.

Result cards have a short entrance animation and scenario buttons have subtle hover feedback. `prefers-reduced-motion` disables animation/transitions. The visible **Sound effects** toggle starts off; an optional preference is stored under `my-jinni-sound`. After an explicit user gesture, Web Audio can synthesise a brief, quiet feedback tone without external media. No sound plays on page load, including when an earlier preference was enabled. Unsupported/blocked audio never interrupts calculations. Automated checks establish requested synthesis and volume settings, not human audibility.

## Architecture and parity

`web/index.html`, `web/styles.css` and `web/decision-app.mjs` provide the primary scenario/priority/comparison view, collapsed tools and result/error states. `web/app.mjs` preserves the optional activity planner, source selection and original-text viewing. Both application modules call `web/platform.mjs`: browser calculations and IndexedDB stay local; Electron calls named preload methods for the actual Python decisions and SQLite library. Native import uses the main-process picker and never passes renderer paths or bytes. The source facade returns the canonical saved ID for selection. Browser TXT/PDF import remains local PDF.js extraction. Dynamic content is inserted as text, never executable HTML. The Content Security Policy restricts scripts, document extraction and network connections to local site assets. Both platforms use this same HTML/CSS/JavaScript interface without a new UI framework. `web/effects.mjs` isolates optional failure-tolerant sound synthesis from calculations.

`web/decisions.mjs` exports pure `evaluateDecision(request, entry)`, returning the full `{data,error,warnings}` envelope over `{scenario,dataset}`. It first excludes unknown/unavailable options, missing required measurements and hard-limit violations. Positive-weight criteria are min/max-normalised over feasible options only; constant criteria score 1. Weighted scores and contribution points round to six decimals; equal scores tie-break by option ID. Raw measures and unrounded normalisation are retained. Relative scores express only the supplied preference model, not probabilities or truth. The same core accepts configured domains without requiring student identity.

`web/planner.mjs` is a pure JavaScript decision layer: budget, outbound-arrival and return-deadline constraints all accept equality; ranking is interest match, total cost, total travel time, then event ID. Integer pence and aware timestamps preserve the Python contract. London date/time conversion is independent of the visitor's timezone. Missing/unavailable travel excludes an event and remains visible in warnings. Changes to form inputs clear the prior result.

`scripts/build_pages.py` calls the actual backend decision-detail routes, which fetch both fictional HTTP feed shapes through bounded source adapters. It exports validated `{scenarios:[{scenario,dataset}]}` to `decisions.json`. The legacy activity export still obtains API options and real feed adapters for each origin into `scenario.json`. Neither export contains precomputed successful rankings. Every browser request calculates a fresh result locally; failed/unvalidated data loading has a visible retry state and no automatic fallback. Future rule changes must preserve Python/browser parity before deployment.

`web/library.mjs` separates persistence and selected-source lexical retrieval from UI. Browser PDF.js extraction is bounded and local. Exact text/page provenance helps users inspect a result, but neither keyword matching nor a simulation flag proves source truth. User text is treated only as data.

## Build and test

Prerequisites are Node 22.12+ (Node 24 recommended), npm, Python 3.12 and uv. Install with `uv sync --locked` and `npm ci` in the repository root, then:

```sh
npm run build:pages
npm run lint:web
npm run test:web
uv run pytest tests/test_pages.py tests/test_decision_pages.py
npx playwright install chromium
npm run test:web:e2e
```

`dist/pages/` is the complete artifact, including local PDF.js assets and its Apache 2.0 license. Do not commit `dist/` or `node_modules/`. Build scripts only recreate `dist/pages`, not application source or the OpenAPI contract. To inspect it manually, serve that directory using any static HTTP server; ES modules/PDF workers require HTTP rather than opening a `file:` URL.

The browser tests serve the exact build under `/my-jinni/`, mirroring the project Pages path. They use a browser timezone in America/Los_Angeles to check London-time independence. If Chromium is already installed locally, set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` to its executable; CI installs the version supplied by Playwright. These are headless browser checks with no Python runtime server, cloud provider, or provider-response mocks.

## Publish

1. Push or merge the change to `main` on `wahab-linux/my-jinni`.
2. In the repository's **Settings → Pages**, choose **GitHub Actions** as the build source. GitHub Pages must be available for the repository's visibility/account plan.
3. Open **Actions → Test and deploy browser app**. The workflow runs Python, desktop-unit and browser checks, builds `dist/pages/`, then deploys the artifact to the `github-pages` environment. Pull requests run checks without deploying. After enabling Pages, rerun the workflow if the first deployment failed before activation.
4. Follow the successful deployment's URL, normally **https://wahab-linux.github.io/my-jinni/**. Calculate all five scenario presets, change priorities/limits and inspect exclusions. Open the library to import/search a fictional guide. Expand the optional activity itinerary for GBP 10 → Board Game Night / GBP 5, GBP 4 → Acoustic Hour, GBP 0 → no match and the city-centre case. Check themes and opt-in sound. Confirm the URL actually serves the deployed application before announcing it as live.

Workflow permissions are limited to repository read in the build job and Pages/ID-token write in the deployment job. No API keys or repository secrets are required. GitHub's environment protection settings may require the repository owner's deployment approval. A local commit, local test result or successful push does not prove a hosted deployment succeeded.
